## Recently Completed

- nodeB idle-crash root-cause fix + gateway inventory resilience (2026-06-26): nodeB services (inventory/payments/rewards) were silently dying after an idle period (machine sleep / local RabbitMQ restart), which surfaced to the FE as `POST /products/with-inventory/multiple` and `GET /products/with-inventory/all` returning **500 AggregateError** (ECONNREFUSED to inventory:3002) and `GET /products/shop/stats` 502. **Root cause:** `RmqModule.registerDirectPublisher()` (`libs/common/src/rmq/rmq.module.ts`) opened a raw `amqplib` connection + channel but attached **no `'error'`/`'close'` listeners** — an amqplib connection is an EventEmitter, so an unhandled `'error'` on an idle drop is thrown as an **uncaught exception and crashes the whole service**. The `nest start <svc> --watch` wrapper kept running (and does NOT auto-restart a runtime crash), which masked the dead app process. **Fix (shared lib → all 6 publisher services: inventory/payments/orders/product/social/notification):** the factory now (a) attaches `error`/`close` handlers on both connection and channel (log, never throw), (b) appends `?heartbeat=30` to the URI so dead sockets are detected, (c) connects in the **background** (sync factory returning immediately — a missing/slow broker never blocks or crashes bootstrap; TCP handlers always come up), and (d) **auto-reconnects** every 5s after a drop, exposed through a stable self-healing `Proxy<Channel>` so the 6 injected consumers keep a single reference and `publish()` safely no-ops (returns `false`) while the channel is briefly down. **Secondary fix (gateway `getProductsWithInventory` in `apps/gateway/src/product/product.service.ts`):** the `/with-inventory/multiple` path was the only inventory-aggregation method missing graceful degradation — no `timeout(10000)` on the inventory `.send()` and a bare `throw error` re-raised the raw `AggregateError` as a 500. Now mirrors `getProductWithInventoryById`: `.pipe(timeout(10000))` + `.catch()` → degrade to `inventory: null` when inventory is unreachable, and each per-product fetch is `.catch(() => null)` (the existing `filter(p !== null)` already expected nulls). eslint/prettier/`tsc --noEmit` clean. Runtime-verified after the fix: inventory recompiled and came back on 3002; `POST /api/products/with-inventory/multiple {productIds:[47]}` → 201 with populated inventory (`available=100,total=100,low=false`; previously the 500), and `GET /api/products/shop/stats` (shop `techstore_demo`) → 200 `{productCount:12,totalStock:961,lowStockCount:0}` — which also closes the P2-05 shop-stats runtime-pending item.
